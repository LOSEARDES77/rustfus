# Rustfus component migration audit

Date: 2026-11-02
Mode: audit first, implementation requires approval.
Scope: `crates/rustfus-gui`; source inspection and upstream documentation. No GUI click-through, build, or test run has been performed in this audit.

## Direction

Preserve Rufus' task order (Drive Properties, Format Options, Status), compact desktop form, paired configuration fields, native secondary windows, translated strings, and green progress identity. Use shadcn-egui components rather than replacing the workflow with a dashboard or card grid.

Proposed dials: ENERGY 1 / RHYTHM 1 / MOTION 1. This utility should emphasize safe drive selection and clear operation state, not decoration.

Button text policy: no forced ALL CAPS. Use sentence-case action labels through a single app-owned button constructor; retain meaningful acronyms, product names, and translations. Do not modify the bundled Rufus translation source. If strictly all-lowercase text is intended, confirm that before implementation.

## Compatibility prerequisite

`crates/rustfus-gui/Cargo.toml:15` and `Cargo.lock:994-1030` use eframe/egui 0.36.2. Published shadcn-egui 0.7.0 uses egui and egui_extras ^0.34. These widget/context types cannot be mixed directly.

Recommended migration path: align eframe with 0.34 and adapt the small set of backend APIs affected by that change, then verify the complete workspace. An alternative is maintaining a locally ported shadcn-egui fork on 0.36, which increases maintenance cost. Do not silently add both egui versions and assume they interoperate.

## Findings for approval

### 1. LOW: component construction and identity are scattered

Rules: R-11, R-20, R-31. Reason: widgets and their visual treatment are constructed independently across the main window and dialogs rather than through one app design layer.

Evidence:
- `widgets.rs:13-33`: manual egui visual/spacing overrides.
- `widgets.rs:108-120`: hand-painted section separator.
- `widgets.rs:162-184`: raw ComboBox wrapper.
- `app/sections.rs`: raw buttons, selects, checkboxes, input, slider, progress, menus and icon glyphs.
- `app/dialogs.rs`: raw modal shell, buttons, form controls, progress and spinner.

Proposed fix: introduce a Rufus-specific theme and shared component adapters backed by shadcn-egui Button, Select, Checkbox, Input, Slider, Progress, Separator, Dialog, Popover and relevant available components. Use supported app variants/sizes instead of custom painting. Keep ordinary text/layout primitives where appropriate. Preserve native file pickers, OS viewport plumbing, and scrolling; these are not substitutes for shadcn components. Where upstream has no equivalent (such as a radio group), retain an explicitly documented themed egui fallback or use an appropriate supported selection component without changing semantics.

Typography should remain readable at the compact desktop size, with multilingual fallback fonts preserved. Green should continue to communicate operation status; small radii and neutral surfaces should preserve the utility's identity. No new visual assets are needed.

### 2. MEDIUM: action labels explicitly force uppercase

Rules: R-06, R-20; explicit user requirement. Reason: forced uppercase overrides translated casing and conflicts with the requested button identity.

Evidence:
- `app/sections.rs:98-99`: Select/Download use `to_uppercase()`.
- `app/sections.rs:341,351,365`: Cancel/Close/Start use `to_uppercase()`.
- `widgets.rs:187-197` and `app/dialogs.rs`: other button constructors bypass any shared text policy; translations may already contain all-cap labels such as OK.

Proposed fix: route every action button, including menu actions and dialog actions, through an app-owned constructor that enforces the agreed non-shouting casing policy. Add tests covering all-cap source labels, mixed-case/acronym labels, Unicode, and source-level checks preventing raw button construction/uppercase transforms outside the design layer. Preserve casing of data options such as MBR, GPT and FreeDOS.

### 3. HIGH: advanced toggles and modal dismissal need keyboard semantics

Rules: R-32, R-26. Reason: advanced toggles are clickable labels without explicit button semantics, while modal dismiss requests are not applied to application state.

Evidence:
- `widgets.rs:123-134`: `Label::sense(Sense::click())`, with no button widget metadata or explicit key handling in this helper.
- `app/dialogs.rs:18-25`: modal response is discarded; no Escape handling closes the active `Dialog`.
- `widgets.rs:221-225`: secondary windows handle OS close requests but do not explicitly handle Escape.

Proposed fix: use focused shadcn buttons with expanded state for advanced sections. Wire modal dismissal and Escape to the appropriate safe cancel path, never to approval or starting a write. Give icon buttons accessible action names. Validate Tab, Shift+Tab, Space/Enter and Escape with headless interaction tests and native checks where possible.

### 4. HIGH: ready-state text fails contrast

Rule: R-25. Reason: white text on the current ready-state green is below the minimum contrast ratio.

Evidence:
- `widgets.rs:10`: `RUFUS_GREEN = #06B025`.
- `app/sections.rs:301-305`: ready progress bar uses white text on that green.
- Contrast checker: `#FFFFFF` / `#06B025` = **2.90:1**, failing normal text (4.5:1) and large text (3:1).

Proposed fix: retain green as the progress identity, but choose a verified foreground/background pair or separate the status label from the progress track. Verify text, focus and error colors in both shipped themes. Do not assert a full theme contrast pass without rendering/measurement.

### 5. HIGH: drive discovery hides loading and error states

Rule: R-27. Reason: failed scans are discarded and an initial scan is indistinguishable from an empty drive list.

Evidence:
- `app/mod.rs:149-162`: scanner only sends successful results; errors never reach the UI.
- `app/sections.rs:19`: no selected drive renders an empty select label.
- `app/mod.rs:583-594`: status reports drive counts but no scanning/failure state.

Proposed fix: expose initial scanning, no eligible drives, and scan failure as distinct states, with a retry action for failures. Use genuine scanner results; never invent device data. This is an adjacent state-handling change, so it can be approved separately from the visual migration.

## Validation after approval

- Format, compile, clippy and test the entire workspace.
- Verify one interoperable egui version after dependency alignment.
- Test shared casing policy and migration coverage.
- Exercise selection changes, advanced settings, disabled/busy controls, Start confirmation/cancel, download steps, hashes, language selection, log/about/settings and both themes without writing to a physical drive.
- Verify dialog Escape never starts a destructive operation.
- Inspect long translated labels and compact window sizing for clipping after component heights change.
- Record which controls were tested automatically, clicked natively, or only inspected; do not claim unperformed click-through tests.
